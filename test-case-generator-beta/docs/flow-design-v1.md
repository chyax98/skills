# 测试用例生成流程设计 V1

## 任务定义

### 输入
- PRD / 功能描述 / 产品原型 / 接口文档 / 用户故事

### 目标
1. 覆盖完整：所有功能点的正向和反向场景
2. 无重复：用例名称唯一，相似度 < 0.75
3. 可执行：步骤具体，可直接用于测试
4. 可导入：格式符合测试平台要求

### 输出
| 文件 | 用途 |
|-----|------|
| {需求名称}-测试用例.jsonl | 最终用例 |
| {需求名称}-测试用例.xlsx | 导入测试平台 |
| {需求名称}-测试用例.xmind | 评审用 |
| check-report.md | 检测报告 |

### 成功标准
1. 格式校验 0 错误
2. 重复用例 0 个
3. 优先级分布：P1(10-20%) P2(25-35%) P3(20-30%) P4(15-25%) P5(5-15%)
4. 每个测试项至少 1 正向 + 1 反向用例

---

## 用例 Schema

```typescript
interface TestCase {
  name: string;           // "验证" 开头，唯一
  priority: "P1"|"P2"|"P3"|"P4"|"P5";
  is_negative: boolean;
  test_type: string;      // 功能测试等
  preconditions: string[];
  steps: Array<{ action: string; expected?: string }>;
  notes?: string;
}
```

---

## 流程

```
Phase 1: 理解需求
    ↓
Phase 2: 规划（模块 + 测试项 → TodoWrite）
    ↓
Phase 3: 逐模块生成
    ├── 生成测试项.jsonl
    ├── 合并单模块 + 模块内检测
    └── 自审 → 下一个模块
    ↓
Phase 4: 全量合并 + 跨模块检测
    ↓
Phase 5: 评估 + 修正
    ↓
Phase 6: 导出
```

---

## Phase 1: 理解需求

读取需求文档，理解业务全貌。

**输出**：对需求的理解（内部）

---

## Phase 2: 规划

1. 划分模块（≤8）
2. 识别每个模块下的测试项
3. 使用 TodoWrite 建立任务清单
4. 创建目录结构

```bash
mkdir -p {workspace}/{模块}/
```

**CRITICAL**：测试项粒度控制，单个测试项预估用例数 ≤ 30，超过则拆分

**输出**：目录结构 + TodoWrite 任务清单

---

## Phase 3: 逐模块生成

```python
for 模块 in 所有模块:
    for 测试项 in 模块.测试项:
        # 3.1 生成用例
        生成完整用例 → {模块}/{测试项}.jsonl

        # 3.2 即时校验
        validate.py {测试项}.jsonl

    # 3.3 合并单模块
    merge.py {模块}/*.jsonl → {模块}/{模块}.jsonl

    # 3.4 模块内重复检测
    check.py {模块}.jsonl --module-level

    # 3.5 模块自审
    执行模块自审检查清单

    # 3.6 继续下一个模块
```

### 3.1 生成用例规则

**用例名称**：
- 以"验证"开头
- 主谓宾结构
- 包含具体场景和预期结果
- 示例：`验证用户输入超过20字符的用户名时系统提示错误`

**优先级判定**：
| 场景类型 | 功能重要性高 | 功能重要性中 | 功能重要性低 |
|---------|------------|------------|------------|
| 正向场景 | P1 | P2 | P3 |
| 反向场景 | P2 | P3 | P4 |
| 边界/异常 | P3 | P4 | P5 |

**步骤规则**：
- action 必须具体可执行，包含具体值
- expected 只在验证点写，过渡步骤省略
- 步骤数量控制在 3-7 步

### 3.5 模块自审检查清单

- [ ] 每个测试项 ≥1 正向 + ≥1 反向
- [ ] 用例名称无重复
- [ ] 用例名称以"验证"开头
- [ ] 优先级分布初步合理
- [ ] steps 非空，至少一个 expected
- [ ] validate.py 通过

---

## Phase 4: 全量合并 + 跨模块检测

```bash
# 4.1 合并所有模块
merge.py {workspace}/*/*.jsonl \
    -o {需求名称}-测试用例.jsonl \
    --sort-by priority

# 4.2 跨模块检测
check.py {需求名称}-测试用例.jsonl -o check-report.md
```

### 检测内容

1. **格式校验**：必填字段、类型检查
2. **优先级分布**：是否符合目标比例
3. **重复检测**：相似度 ≥ 0.75 的用例对
4. **乱码检测**：异常字符
5. **覆盖检测**：每个测试项是否有正向+反向

---

## Phase 5: 评估 + 修正

读取 check-report.md，逐项评估：

### 优先级分布异常
- P1 过高（>20%）：降级部分非核心功能的 P1 用例
- P1 过低（<10%）：检查是否遗漏核心正向场景
- 按比例调整，使用脚本辅助批量修改

### 重复用例处理
| 情况 | 处理 |
|-----|------|
| 完全重复（相似度 >0.95） | 删除其中一个 |
| 高度相似（0.85-0.95） | 合并或保留差异较大的 |
| 中度相似（0.75-0.85） | 检查是否测同一场景，是则合并 |

### 乱码处理
- 定位并修复

### 修正后重新检测
```bash
check.py {需求名称}-测试用例.jsonl -o check-report-v2.md
```

**循环直到**：check-report 无严重问题

---

## Phase 6: 导出

```bash
export.py {需求名称}-测试用例.jsonl -o {需求名称}-测试用例
# 同时输出 .xlsx 和 .xmind
```

**输出确认**：
- [ ] {需求名称}-测试用例.jsonl
- [ ] {需求名称}-测试用例.xlsx
- [ ] {需求名称}-测试用例.xmind
- [ ] check-report.md（最终版）

## 脚本清单

| 脚本 | 功能 |
|-----|------|
| validate.py | 单文件格式校验 |
| merge.py | 合并 JSONL |
| check.py | 综合检测（优先级、重复、乱码、覆盖） |
| export.py | 导出 Excel + XMind |

---

## 风险应对

| 风险 | 应对 |
|-----|------|
| 用例数目庞大 | 测试项粒度控制，单测试项 ≤30 用例 |
| 重复率高 | 模块内+跨模块双重检测 |
| 优先级分布失衡 | Phase 5 评估调整 |

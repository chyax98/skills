# 测试用例生成流程设计

## 任务定义

### 输入
- PRD / 功能描述 / 产品原型 / 接口文档 / 用户故事

### 目标
1. 覆盖完整：所有功能点的正向和反向场景
2. 无重复：用例名称唯一，相似度 < 0.75
3. 可执行：步骤具体，可直接用于测试
4. 可导入：格式符合测试平台要求

### 输出
| 文件 | 用途 |
|-----|------|
| {需求名称}-测试用例.jsonl | 最终用例 |
| {需求名称}-测试用例.xlsx | 导入测试平台 |
| {需求名称}-测试用例.xmind | 评审用 |
| check-report.md | 检测报告 |

### 成功标准
1. 格式校验 0 错误
2. 重复用例 0 个（相似度 ≥ 0.75）
3. 优先级分布：P1(10-20%) P2(25-35%) P3(20-30%) P4(15-25%) P5(5-15%)
4. 每个测试项至少 1 正向 + 1 反向用例

---

## Workspace 定义

**CRITICAL**：workspace = 需求名称，作为根目录

```bash
# 示例：需求名称为"用户管理系统"
workspace="用户管理系统"
mkdir -p "${workspace}"
cd "${workspace}"  # 后续命令在此目录下执行
```

所有脚本命令均在 workspace 父目录下执行，脚本位于 `scripts/` 目录。

---

## 用例 Schema

```typescript
interface TestCase {
  name: string;           // "验证" 开头，唯一
  priority: "P1"|"P2"|"P3"|"P4"|"P5";
  is_negative: boolean;
  test_type: string;      // 功能测试等
  preconditions: string[];
  steps: Array<{ action: string; expected?: string }>;
  notes?: string;
}
```

**CRITICAL**：用例名称 = 测试点，必须包含：场景 + 预期结果

## 流程概览

```
Phase 1: 理解需求
    ↓
Phase 2: 规划（模块 + 测试项 → TodoWrite）
    ↓
Phase 3: 逐模块生成
    ├── 生成测试项.jsonl
    ├── 合并单模块 + 模块内检测
    └── 自审 → 下一个模块
    ↓
Phase 4: 全量合并 + 跨模块检测
    ↓
Phase 5: 评估 + 修正
    ↓
Phase 6: 导出
```

---

## Phase 1: 理解需求

读取需求文档，理解业务全貌。

**输出**：对需求的理解（内部）

---

## Phase 2: 规划

1. 划分模块（≤8）
2. 识别每个模块下的测试项
3. 使用 TodoWrite 建立任务清单
4. 创建目录结构

```bash
mkdir -p ${workspace}/{模块名}/
```

**CRITICAL**：测试项粒度控制
- 单个测试项预估用例数 ≤ 30
- 超过则拆分为多个测试项

**输出**：目录结构 + TodoWrite 任务清单

---

## Phase 3: 逐模块生成

```python
for 模块 in 所有模块:
    for 测试项 in 模块.测试项:
        # 3.1 生成用例
        生成完整用例 → ${workspace}/${模块}/${测试项}.jsonl

        # 3.2 即时校验
        python3 validate.py ${workspace}/${模块}/${测试项}.jsonl

    # 3.3 合并单模块
    python3 merge.py ${workspace}/${模块}/*.jsonl \
        -o ${workspace}/${模块}/_merged.jsonl

    # 3.4 模块内重复检测
    python3 check.py ${workspace}/${模块}/_merged.jsonl --module-level

    # 3.5 模块自审
    执行模块自审检查清单

    # 3.6 继续下一个模块
```

### 3.1 生成用例规则

**CRITICAL - 用例名称规范**：
- 以"验证"开头
- 主谓宾结构：验证 + [主体] + [动作/条件] + [预期结果]
- 包含具体场景和预期结果
- 示例：
  - ✅ `验证用户输入超过20字符的用户名时系统提示长度错误`
  - ✅ `验证未登录用户访问个人中心时跳转到登录页`
  - ❌ `验证用户名长度` （缺少预期结果）
  - ❌ `用户名超长测试` （未以"验证"开头）

**优先级判定矩阵**：
| 场景类型 | 功能重要性高 | 功能重要性中 | 功能重要性低 |
|---------|------------|------------|------------|
| 正向场景 | P1 | P2 | P3 |
| 反向场景 | P2 | P3 | P4 |
| 边界/异常 | P3 | P4 | P5 |

功能重要性判断：
- **高**：核心业务流程、支付、数据安全
- **中**：常用功能、数据展示
- **低**：边缘功能、辅助功能

**前置条件规则**：
- 描述执行用例前必须满足的状态
- 示例：`["用户已登录", "购物车有商品"]`
- 无前置条件时使用空数组 `[]`

**步骤规则**：
- action 必须具体可执行，包含具体值
- expected 只在验证点写，过渡步骤省略
- 步骤数量控制在 3-7 步

**测试类型**：参考 `references/test-type-guide.md`

### 3.5 模块自审检查清单

- [ ] 每个测试项 ≥1 正向 + ≥1 反向
- [ ] 用例名称无重复
- [ ] 用例名称以"验证"开头且包含预期结果
- [ ] 优先级分布初步合理
- [ ] steps 非空，至少一个 expected
- [ ] validate.py 通过

## Phase 4: 全量合并 + 跨模块检测

```bash
# 4.1 合并所有模块（排除 _merged.jsonl）
python3 merge.py ${workspace}/*/_merged.jsonl \
    -o ${workspace}/${需求名称}-测试用例.jsonl \
    --sort-by priority

# 4.2 跨模块检测
python3 check.py ${workspace}/${需求名称}-测试用例.jsonl \
    -o ${workspace}/check-report.md
```

### check.py 输出格式

```markdown
# 检测报告

## 概要
- 总用例数：N
- 检测时间：YYYY-MM-DD HH:MM

## 1. 格式校验
- 通过：N 条
- 失败：N 条
  - [文件:行号] 错误描述

## 2. 优先级分布
| 优先级 | 数量 | 占比 | 目标范围 | 状态 |
|-------|-----|------|---------|------|
| P1 | N | X% | 10-20% | ✅/⚠️ |
...

## 3. 重复检测
发现 N 对相似用例（阈值 0.75）：
| 用例1 | 用例2 | 相似度 | 建议 |
|------|------|-------|------|
| ... | ... | 0.XX | 删除/合并 |

## 4. 乱码检测
- 发现 N 处异常字符
  - [文件:行号] 字段名：异常内容

## 5. 覆盖检测
| 测试项 | 正向 | 反向 | 状态 |
|-------|-----|------|------|
| ... | N | N | ✅/❌ |
```

---

## Phase 5: 评估 + 修正

读取 check-report.md，逐项评估并修正。

### 优先级调整策略

**P1 过高（>20%）**：
1. 识别非核心功能的 P1 用例
2. 反向场景的 P1 → P2
3. 边界场景的 P1 → P2/P3

**P1 过低（<10%）**：
1. 检查核心功能正向场景是否标记为 P1
2. 支付、登录、数据提交等核心流程应为 P1

**调整方式**：直接编辑 JSONL 文件修改 priority 字段

### 重复用例处理

**CRITICAL - 重复检测阈值**：相似度 ≥ 0.75 视为重复

| 相似度 | 情况 | 处理 |
|-------|-----|------|
| > 0.95 | 完全重复 | 删除其中一个 |
| 0.85-0.95 | 高度相似 | 合并或保留差异较大的 |
| 0.75-0.85 | 中度相似 | 检查是否测同一场景，是则合并 |

### 修正后重新检测

```bash
python3 check.py ${workspace}/${需求名称}-测试用例.jsonl \
    -o ${workspace}/check-report-v2.md
```

**循环直到**：
- 格式校验 0 错误
- 重复用例 0 个
- 优先级分布在目标范围内

## Phase 6: 导出

```bash
python3 export.py ${workspace}/${需求名称}-测试用例.jsonl \
    -o ${workspace}/${需求名称}-测试用例
# 同时输出 .xlsx 和 .xmind
```

**输出确认**：
- [ ] {需求名称}-测试用例.jsonl
- [ ] {需求名称}-测试用例.xlsx
- [ ] {需求名称}-测试用例.xmind
- [ ] check-report.md（最终版，无严重问题）

## 风险应对

| 风险 | 应对 |
|-----|------|
| 用例数目庞大 | 测试项粒度控制，单测试项 ≤30 用例 |
| 重复率高 | 模块内+跨模块双重检测 |
| 优先级分布失衡 | Phase 5 评估调整 |
| 用例名称不规范 | CRITICAL 标记 + 自审检查清单 |

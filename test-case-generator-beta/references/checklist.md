# 完整检查清单

## Phase 1: 规划

### 模块划分
- [ ] 模块数量 ≤8
- [ ] 模块按功能内聚划分
- [ ] 模块名称清晰准确

### 测试项识别
- [ ] 每个用户操作 = 1 个测试项
- [ ] 每个系统行为 = 1 个测试项
- [ ] CRUD 各独立为测试项
- [ ] 无遗漏关键功能

### 功能等级
- [ ] 核心功能：失败导致系统核心价值丧失（10-15%）
- [ ] 基本功能：失败影响体验但不阻塞核心（60-70%）
- [ ] 不常用功能：低频扩展功能（15-25%）

---

## Phase 2: 设计测试点

### 命名规范
- [ ] 以"验证"开头
- [ ] 主谓宾结构完整
- [ ] 描述具体验证内容
- [ ] 无歧义，可区分

```
✅ 验证用户成功创建订单
✅ 验证系统拒绝超过50字符的用户名
✅ 验证未登录用户访问个人中心时跳转登录页

❌ 登录测试（缺少验证对象）
❌ 密码错误（缺少验证动作）
❌ 测试用户注册功能（不是验证点）
```

### 覆盖完整性
- [ ] 核心功能：正向 + 边界 + 异常 + 性能/安全
- [ ] 基本功能：正向 + 边界 + 异常
- [ ] 不常用功能：正向 + 主要异常
- [ ] 每测试项 ≥1 正向 + ≥1 反向

### 优先级判定
- [ ] 核心功能正向 → P1
- [ ] 基本功能正向 → P2
- [ ] 核心功能反向 → P3
- [ ] 基本功能反向 → P4
- [ ] 不常用功能 → P5

### 去重
- [ ] 无完全重复测试点
- [ ] 无高度相似测试点（相似度 <0.75）

---

## Phase 3: 补充细节

### 前置条件
- [ ] 明确具体状态
- [ ] 无废话（如"系统正常"）
- [ ] 无默认条件（如"网络正常"）

```
✅ 用户已登录
✅ 购物车中有商品
✅ 账号连续错误4次

❌ 系统正常
❌ 网络正常
```

### 操作步骤
- [ ] 具体可执行
- [ ] 包含具体值
- [ ] 步骤完整不遗漏
- [ ] 顺序正确

```
✅ 输入用户名 testuser
✅ 输入21个字符的用户名 abcdefghijklmnopqrstu
✅ 点击"提交"按钮

❌ 输入正确的用户名（不具体）
❌ 输入用户名（缺少值）
```

### 预期结果
- [ ] 只在验证点写 expected
- [ ] 过渡步骤不写 expected
- [ ] 预期结果明确可验证
- [ ] 无废话预期

```
✅ 步骤: "点击登录按钮"
   预期: "登录成功，跳转到首页"

✅ 步骤: "输入用户名 testuser"
   （无预期 - 过渡步骤）

❌ 步骤: "输入用户名 testuser"
   预期: "用户名输入框显示 testuser"
```

### 测试类型
- [ ] 功能测试占 50-60%
- [ ] 测试类型与场景匹配
- [ ] 使用标准测试类型

### 格式校验
- [ ] validate.py 通过
- [ ] 无语法错误
- [ ] 必填字段完整

## 常见错误修正

| 错误 | 修正 |
|-----|-----|
| 核心功能反向用例设为 P2 | 改为 P3 |
| 基本功能正向用例设为 P3 | 改为 P2 |
| 所有正向用例都设为 P1 | 按功能等级判定 |
| 名称不以"验证"开头 | 重写名称 |
| steps 无 expected | 至少添加一个验证点 |
| action 不具体 | 添加具体值 |

# 需求分析示例

## 示例 1：登录功能需求分析

### 原始需求

```
用户登录功能：
1. 用户可以使用手机号登录
2. 系统发送验证码
3. 验证成功后进入首页
```

### 分析过程

#### Phase 1: 需求解析

提取功能点：
- F1: 手机号输入
- F2: 验证码发送
- F3: 验证码校验
- F4: 登录成功跳转

#### Phase 2: 多维度分析

**完整性检查**：

| 问题 | 严重程度 | 说明 |
|-----|---------|------|
| 验证码有效期未定义 | 严重 | 不知何时过期 |
| 重发间隔未说明 | 一般 | 可能被恶意刷短信 |
| 错误次数限制未定义 | 严重 | 可能被暴力破解 |
| 手机号格式校验未说明 | 一般 | 需要前端校验规则 |
| 登录态保持时间未定义 | 一般 | token 有效期不明 |

**可测性检查**：

| 问题 | 严重程度 | 说明 |
|-----|---------|------|
| "验证成功"标准不明 | 一般 | 什么算验证成功 |
| 响应时间无要求 | 建议 | 无法测试性能 |

**异常容错检查**：

| 问题 | 严重程度 | 说明 |
|-----|---------|------|
| 网络异常未处理 | 一般 | 发送失败怎么办 |
| 验证码发送失败未处理 | 严重 | 短信服务不可用 |
| 账号不存在未说明 | 一般 | 是否自动注册 |

#### Phase 3: 问题汇总

共发现 10 个问题：
- 阻塞：0 个
- 严重：3 个
- 一般：6 个
- 建议：1 个

#### Phase 4: 规范化输出

```yaml
requirement:
  id: REQ-LOGIN-001
  name: 手机验证码登录
  type: functional
  priority: high

  description: |
    用户使用手机号和短信验证码进行身份验证登录系统

  preconditions:
    - 用户手机号已注册（若未注册则自动创建账户）
    - 用户网络连接正常
    - 短信服务可用

  actors:
    - 注册用户
    - 未注册用户（自动注册场景）

  main_flow:
    - step: 1
      action: 用户输入 11 位手机号
      expected: 系统实时校验格式，错误时提示"请输入正确的手机号"
    - step: 2
      action: 用户点击"获取验证码"
      expected: |
        - 按钮变为倒计时状态（60秒）
        - 系统发送 6 位数字验证码到手机
        - 验证码 60 秒内送达
    - step: 3
      action: 用户输入验证码
      expected: 系统自动校验（输满 6 位自动提交）
    - step: 4
      action: 验证通过
      expected: 跳转到首页，显示用户信息

  alternative_flows:
    - name: 验证码过期
      trigger: 验证码超过 5 分钟
      steps:
        - 提示"验证码已过期，请重新获取"
        - 清空验证码输入框
        - 允许重新获取

    - name: 未注册用户
      trigger: 手机号未在系统注册
      steps:
        - 验证码验证通过后自动创建账户
        - 跳转到首页
        - 提示"欢迎加入"

  exception_flows:
    - name: 手机号格式错误
      trigger: 输入非 11 位数字
      handling: 前端即时提示"请输入正确的手机号"，获取验证码按钮禁用

    - name: 验证码错误
      trigger: 输入的验证码与发送的不匹配
      handling: 提示"验证码错误"，允许重试，连续错误 5 次后锁定 30 分钟

    - name: 短信发送失败
      trigger: 短信网关故障
      handling: 提示"短信发送失败，请稍后重试"，记录日志告警

    - name: 网络异常
      trigger: 请求超时或网络断开
      handling: 提示"网络异常，请检查网络后重试"

  acceptance_criteria:
    - 验证码 60 秒内送达（P99）
    - 登录接口响应时间 < 500ms（P99）
    - 连续输错 5 次验证码锁定账户 30 分钟
    - 验证码有效期 5 分钟
    - 重发间隔 60 秒
    - 登录态保持 7 天

  dependencies:
    - 短信服务（阿里云/腾讯云）
    - 用户数据库
    - Redis（存储验证码和限流计数）

  open_questions: []  # 已全部确认
```

## 示例 2：订单列表需求分析

### 原始需求

```
订单列表页面：
- 显示用户的历史订单
- 可以筛选和搜索
- 点击可查看详情
```

### 分析过程

#### 发现的问题

| 维度 | 问题 | 严重程度 |
|-----|------|---------|
| 完整性 | 显示哪些字段未定义 | 严重 |
| 完整性 | 排序规则未说明 | 一般 |
| 完整性 | 分页规则未定义 | 一般 |
| 完整性 | 筛选维度未列出 | 严重 |
| 完整性 | 搜索范围未说明 | 一般 |
| 完整性 | 空状态设计未提及 | 一般 |
| 可测性 | 列表加载时间无要求 | 建议 |
| 界面规范 | 加载状态未定义 | 一般 |
| 异常容错 | 加载失败处理未说明 | 一般 |

#### 需要确认的问题

1. 订单列表显示哪些字段？（订单号、金额、状态、时间、商品？）
2. 支持哪些筛选条件？（状态、时间范围、金额区间？）
3. 搜索支持哪些字段？（订单号、商品名？）
4. 每页显示多少条？是否支持切换？
5. 是否需要支持批量操作？

## 示例 3：模糊需求识别

### 常见模糊表述及修正

| 原始表述 | 问题 | 修正后 |
|---------|------|-------|
| 系统应快速响应 | "快速"无标准 | 接口响应时间 ≤ 200ms（P99） |
| 支持大量用户 | "大量"不明确 | 支持 10000 并发用户 |
| 界面应友好 | "友好"主观 | 遵循 Material Design 规范 |
| 数据应安全存储 | "安全"范围不清 | 敏感数据 AES-256 加密存储 |
| 可以导出报表 | 格式、内容不明 | 支持导出 Excel 格式，包含 X/Y/Z 字段 |
| 需要权限控制 | 权限粒度不清 | 角色：管理员/编辑/查看者，权限矩阵见附表 |
| 支持多端 | 哪些端不明 | 支持 iOS 12+、Android 8+、Chrome 80+ |
| 做好日志记录 | 记录什么不清 | 记录用户操作日志，包含时间、用户、操作、结果 |

## 分析思维链模板

分析需求时，按以下思维链逐步检查：

```
1. 功能识别
   └─ 这个需求要实现什么功能？
   └─ 涉及哪些用户角色？
   └─ 涉及哪些业务实体？

2. 流程分析
   └─ 正常流程是什么？
   └─ 有哪些分支场景？
   └─ 有哪些异常场景？

3. 边界检查
   └─ 输入有什么限制？
   └─ 输出是什么格式？
   └─ 有哪些极限情况？

4. 一致性验证
   └─ 与其他需求是否冲突？
   └─ 术语使用是否一致？
   └─ 数值范围是否合理？

5. 可测性确认
   └─ 如何验证功能实现正确？
   └─ 验收标准是否可量化？
   └─ 测试数据从哪里来？

6. 可行性评估
   └─ 技术上能实现吗？
   └─ 有什么依赖？
   └─ 有什么风险？

7. 遗漏扫描
   └─ 还缺什么信息？
   └─ 还有什么场景没考虑？
   └─ 还需要问什么问题？
```

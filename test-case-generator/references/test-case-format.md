# 测试用例 Markdown 格式规范

**版本**: v2.0
**日期**: 2025-12-17

---

## 1. 设计原则

- **可读性优先**：Markdown 格式，人类直接可读
- **结构清晰**：层级分明，模块 > 场景 > 用例
- **灵活务实**：非必填字段按需填写，不强制冗余
- **质量不降**：格式简化，规范不简化

---

## 2. 层级结构

```
# 一级分组（模块）
## 二级分组（场景/功能点）
### 用例名称
```

| 层级 | 标记 | 说明 | 必填 |
|------|------|------|------|
| 一级分组 | `#` | 功能模块，如「用户登录」「订单管理」 | 否 |
| 二级分组 | `##` | 场景或功能点，如「正常登录」「异常处理」 | 否 |
| 用例名称 | `###` | 具体测试用例，以"验证"开头 | 是 |

**说明**：
- 分组层级可扩展（支持 N 级），但建议不超过 3 级
- 分组用于组织用例，非必填
- 用例名称是最小单元，必须存在

---

## 3. 用例结构

每个用例包含以下部分：

```markdown
### 用例名称
|测试类型|反向

[前置]前置条件（可选）

[步骤]
1. 操作步骤
2. 操作步骤 ➡️ 预期结果
3. 操作步骤 ➡️ 预期结果

[备注]备注信息（可选）
```

---

## 4. 字段详细说明

### 4.1 用例名称（必填）

- **格式**：以"验证"开头，主谓宾结构
- **位置**：三级标题 `###`

| 正确 | 错误 |
|------|------|
| 验证用户成功登录系统 | 登录测试 |
| 验证密码错误时登录失败 | 密码错误 |
| 验证系统拦截SQL注入 | SQL注入 |

---

### 4.2 元数据（必填）

**格式**：`优先级|测试类型|反向`（用 | 分隔，无空格）

| 组成 | 必填 | 取值 | 说明 |
|------|------|------|------|
| 优先级 | 是 | P1/P2/P3/P4/P5 | 见优先级定义 |
| 测试类型 | 是 | 见测试类型列表 | 功能/安全性/性能等 |
| 反向标记 | 否 | `[反向]` | 正向用例省略此标记 |

**示例**：
```markdown
P1|功能
P2|功能|反向
P2|安全性|反向
```

#### 优先级定义（固定规则）

| 优先级 | 定义 | 判断规则 |
|-------|------|---------|
| P1 | 核心功能正向测试 | 核心业务 + 正向场景 |
| P2 | 基本功能（常用场景）+ 核心功能反向测试 | 基本功能正向 OR (核心业务 + 反向场景) |
| P3 | 基本功能（不常用场景） | 基本功能 + 低频场景 |
| P4 | 基本功能反向测试 | 基本功能 + 反向场景 |
| P5 | 不常用功能测试 | 低频功能 |

#### 测试类型列表

| 类别 | 测试类型 |
|------|---------|
| 基础 | 功能、兼容性、易用性、性能、稳定性、安全性、可靠性 |
| 扩展 | 效果（AI类）、效果（硬件类）、可维护性、可移植性、埋点 |

---

### 4.3 前置条件（非必填）

**格式**：`[前置]` + 条件内容

**两种写法**：

```markdown
# 单行写法
[前置]系统已部署，存在有效账号 test/123456

# 列表写法
[前置]
- 系统已部署
- 存在有效账号 test/123456
- 账户状态正常
```

**说明**：
- 无前置条件时，整个[前置]部分省略
- 条件应具体可验证，避免模糊描述

---

### 4.4 测试步骤（必填）

**格式**：`[步骤]` + 编号列表

```markdown
[步骤]
1. 操作步骤
2. 操作步骤 ➡️ 预期结果
3. 操作步骤 ➡️ 预期结果
```

#### 步骤格式规则

| 格式 | 说明 | 适用场景 |
|------|------|---------|
| `n. 操作` | 仅操作，无预期结果 | 中间步骤、准备动作 |
| `n. 操作 ➡️ 预期结果` | 操作 + 预期结果 | 需要验证的步骤 |

**解析规则**：
- 使用 `➡️` 作为分隔符- `➡️` 前面是操作，后面是预期结果
- 无 `➡️` 时整行为操作，预期结果为空

**示例**：
```markdown
[步骤]
1. 打开浏览器                           # 准备动作，无需验证
2. 访问登录页面 ➡️ 页面正常显示           # 需要验证
3. 输入用户名 test                       # 中间步骤
4. 输入密码 123456                       # 中间步骤
5. 点击登录按钮 ➡️ 登录成功，跳转首页      # 关键验证点
```

#### 步骤编写原则

- **至少 1 步**
- **操作具体可执行**：避免"正确操作"、"按要求输入"等模糊描述
- **预期结果可验证**：避免"正常"、"成功"等模糊词，应具体描述可观察的结果
- **预期结果非必填**：中间步骤、准备动作可省略预期结果

---

### 4.5 备注（非必填）

**格式**：`[备注]` + 备注内容

```markdown
[备注]核心功能冒烟用例，每次发布必须执行
```

**适用场景**：
- 用例背景说明
- 特殊注意事项
- 关联信息（需求、缺陷等）

---

## 5. 用例分隔

用例之间使用 `---` 分隔（可选）：

```markdown
### 验证用户成功登录
P1|功能
...

---

### 验证密码错误时登录失败
P2|功能|反向
...
```

**说明**：分隔线用于视觉区分，非必须

---

## 6. 完整示例

```markdown
# 用户登录

## 正常登录

### 验证用户成功登录系统
P1|功能

[前置]
- 系统已部署
- 存在有效账号 test/123456
- 账户状态正常

[步骤]
1. 打开登录页面 ➡️ 页面显示用户名和密码输入框
2. 输入用户名 test
3. 输入密码 123456
4. 点击登录按钮 ➡️ 登录成功，跳转首页，右上角显示用户名

[备注]核心冒烟用例

---

### 验证记住密码功能正常
P3|功能

[前置]用户已注册

[步骤]
1. 打开登录页面
2. 勾选"记住密码" ➡️ 选项被勾选
3. 输入正确用户名密码并登录 ➡️ 登录成功
4. 退出登录
5. 重新打开登录页面 ➡️ 用户名密码自动填充

---

## 异常登录

### 验证密码错误时登录失败
P2|功能|反向

[前置]存在有效账号 test

[步骤]
1. 打开登录页面
2. 输入用户名 test 和错误密码 wrongpass
3. 点击登录按钮 ➡️ 提示"用户名或密码错误"，不泄露账户是否存在

---

### 验证连续错误登录触发锁定
P2|功能|反向

[前置]存在有效账号 test，错误次数阈值为5次

[步骤]
1. 连续输入错误密码5次 ➡️ 每次提示"用户名或密码错误"
2. 第6次尝试登录 ➡️ 提示"账户已锁定，请30分钟后重试"
3. 使用正确密码登录 ➡️ 仍提示账户锁定

---

## 安全验证

### 验证系统拦截SQL注入攻击
P2|安全性|反向

[步骤]
1. 打开登录页面
2. 在用户名输入 ' OR '1'='1
3. 点击登录按钮 ➡️ 登录失败，提示输入错误
4. 检查后台日志 ➡️ SQL语句被转义，无注入痕迹

[备注]确保使用参数化查询或ORM

---

### 验证密码传输加密
P2|安全性

[步骤]
1. 打开浏览器开发者工具，切换到Network面板
2. 执行登录操作
3. 查看登录请求 ➡️ 请求使用HTTPS，密码字段已加密或哈希处理
```

## 7. 格式速查表

| 元素 | 格式 | 必填 |
|------|------|------|
| 一级分组 | `# 分组名` | 否 |
| 二级分组 | `## 分组名` | 否 |
| 用例名称 | `### 验证xxx` | 是 |
| 元数据 | `P1|功能|反向` | 是（反向标记可选） |
| 前置条件 | `[前置]条件内容` | 否 |
| 测试步骤 | `[步骤]` + 编号列表 | 是 |
| 预期结果 | `操作 ➡️ 预期结果` | 否（按需填写） |
| 备注 | `[备注]备注内容` | 否 |
| 用例分隔 | `---` | 否 |

---

## 8. 反向用例判断

**按输入类型判断**：

| 输入类型 | 是否反向 | 示例 |
|---------|---------|------|
| 正常/有效输入 | 否 | 正确用户名密码 |
| 异常/无效输入 | 是 | 错误密码、不存在的用户 |
| 边界值输入 | 是 | 密码长度为1或128 |
| 攻击性输入 | 是 | SQL注入、XSS脚本 |
| 空值/缺失输入 | 是 | 不填用户名提交 |

---

## 9. 与原 JSONL 格式对照

| JSONL 字段 | Markdown 格式 | 变化 |
|-----------|--------------|------|
| id | - | 移除，由层级结构定位 |
| name | `### 用例名称` | 保留 |
| module_name | `# 一级分组` | 保留 |
| test_item | `## 二级分组` | 保留 |
| scenario_type | - | 移除，融入分组名称 |
| priority | `[P1]` | 保留 |
| test_type | `[功能]` | 保留 |
| is_negative | `[反向]` | 保留，正向时省略 |
| preconditions | `[前置]` | 保留，非必填 |
| steps[].action | 步骤编号列表 | 保留 |
| steps[].expected | `\| 预期结果` | 保留，非必填 |
| notes | `[备注]` | 保留，非必填 |

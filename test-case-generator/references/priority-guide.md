# 测试用例优先级判断指南

## 优先级定义

| 优先级 | 定义 | 执行频率 | 失败影响 |
|-------|-----|---------|---------|
| P1 | 核心功能正向测试（冒烟测试） | 每次构建必须执行 | 阻塞发布 |
| P2 | 基本功能测试（常用场景） + 核心功能反向测试（重要错误/边界值） | 每日回归测试 | 影响用户体验/系统健壮性 |
| P3 | 基本功能测试（不常用场景） | 版本回归测试 | 影响部分场景 |
| P4 | 基本功能反向测试（异常/边界） | 完整回归测试 | 影响边界场景 |
| P5 | 不常用功能测试 | 发布前完整测试 | 影响极少数用户 |

---

## 详细说明

### P1：核心功能正向测试（冒烟测试）

**定义**：系统最关键业务流程的正常场景

**典型场景**：
- 用户登录成功
- 订单创建成功
- 支付完成
- 数据保存成功

**示例**：
| 用例 | 测试项 | 场景 |
|-----|-------|-----|
| 验证用户成功登录系统 | 用户登录 | 正常登录流程 |
| 验证订单创建成功 | 订单管理 | 正常下单流程 |
| 验证支付成功完成 | 支付功能 | 正常支付流程 |

---

### P2：基本功能测试（常用场景） + 核心功能反向测试

**定义**：常用辅助功能的正常场景 + 核心功能的异常处理和边界条件

**典型场景**：
- **基本功能常用**：修改个人信息、订单查询、消息通知、数据导出
- **核心功能反向**：登录密码错误、支付金额边界值、权限校验失败、订单状态冲突

**示例**：
| 用例 | 测试项 | 场景 | 类型 |
|-----|-------|-----|-----|
| 验证用户修改昵称成功 | 个人信息 | 修改昵称 | 基本功能正向 |
| 验证订单列表正确展示 | 订单查询 | 查询历史订单 | 基本功能正向 |
| 验证密码错误时登录失败 | 用户登录 | 密码错误处理 | 核心功能反向 |
| 验证支付金额为0时拒绝 | 支付功能 | 金额边界值 | 核心功能反向 |
| 验证重复支付被拦截 | 支付功能 | 重复操作处理 | 核心功能反向 |

---

### P3：基本功能测试（不常用场景）

**定义**：低频使用的基本功能

**典型场景**：
- 修改密码（用户偶尔才用）
- 切换语言
- 查看历史记录
- 高级筛选

**示例**：
| 用例 | 测试项 | 场景 |
|-----|-------|-----|
| 验证用户成功修改密码 | 密码管理 | 修改密码 |
| 验证切换语言成功 | 语言设置 | 切换语言 |
| 验证高级筛选正确过滤 | 数据查询 | 多条件筛选 |

---

### P4：基本功能反向测试（异常/边界）

**定义**：辅助功能的异常处理和边界条件验证

**典型场景**：
- 上传文件格式错误
- 输入字段长度超限
- 并发操作冲突
- 网络异常处理

**示例**：
| 用例 | 测试项 | 场景 |
|-----|-------|-----|
| 验证头像格式错误时提示 | 个人信息 | 格式校验 |
| 验证昵称超长时截断 | 个人信息 | 长度边界 |
| 验证网络断开时提示 | 网络处理 | 异常提示 |

---

### P5：不常用功能正反向测试

**定义**：低频使用的扩展功能测试

**典型场景**：
- 高级搜索功能
- 管理员统计报表
- 数据批量导入
- 自定义配置

**示例**：
| 用例 | 测试项 | 场景 |
|-----|-------|-----|
| 验证高级搜索正确过滤 | 高级搜索 | 多条件过滤 |
| 验证管理员导出报表 | 统计报表 | 数据导出 |
| 验证批量导入数据 | 数据导入 | 批量操作 |

---

## 判断决策树

```
开始
├─ 是核心业务流程？（登录、支付、下单等）
│  ├─ 是
│  │  ├─ 是正向场景？
│  │  │  ├─ 是 → P1
│  │  │  └─ 否 → P2（核心功能反向）
│  └─ 否
│     ├─ 是基本功能？
│     │  ├─ 是
│     │  │  ├─ 是常用场景？
│     │  │  │  ├─ 是正向？ → P2（基本功能常用）
│     │  │  │  └─ 是反向？ → P4
│     │  │  ├─ 是不常用场景？ → P3
│     │  │  └─ 是反向场景？ → P4
│     └─ 是不常用功能？
│        └─ 是 → P5
```

---

## 优先级映射表

| 功能重要性 | 场景类型 | 使用频率 | 优先级 |
|-----------|---------|---------|-------|
| 核心功能 | 正向场景 | - | P1 |
| 核心功能 | 反向场景 | - | P2 |
| 基本功能 | 正向场景 | 常用 | P2 |
| 基本功能 | 正向场景 | 不常用 | P3 |
| 基本功能 | 反向场景 | - | P4 |
| 不常用功能 | 正反向场景 | - | P5 |

---

## 特殊场景处理

### 性能测试
- 核心功能性能测试 → P2
- 基本功能性能测试 → P4
- 极端压力测试 → P5

### 安全测试
- 认证授权安全测试 → P1/P2
- 注入攻击防护测试 → P3
- 高级渗透测试 → P4

### 兼容性测试
- 主流环境兼容性 → P2
- 次要环境兼容性 → P4

### 集成测试
- 核心模块集成 → P1/P2
- 辅助模块集成 → P3/P4

---

## 优先级分布建议

| 优先级 | 建议占比 | 说明 |
|-------|---------|-----|
| P1 | 10-15% | 核心业务正向场景 |
| P2 | 35-40% | 基本功能常用 + 核心功能反向 |
| P3 | 15-20% | 基本功能不常用场景 |
| P4 | 20-25% | 基本功能反向场景 |
| P5 | 5-10% | 不常用功能 |

**说明**：P2 占比最高是因为包含了两类用例：基本功能常用场景 + 核心功能反向场景

---

## 常见错误

### 错误 1：核心功能反向用例设为 P3 或 P4
❌ 错误：将「登录密码错误」设为 P3 或 P4
✅ 正确：P2（核心功能反向场景，优先级高于基本功能正向）

**原因**：核心业务的容错性比普通功能更重要

### 错误 2：基本功能常用场景设为 P3
❌ 错误：将「查询订单列表」设为 P3
✅ 正确：P2（基本功能但常用，使用频率高）

**原因**：常用功能即使非核心，也应优先测试

### 错误 3：所有正向用例都设为 P1
❌ 错误：将「修改头像」设为 P1
✅ 正确：P2（基本功能正向场景，非核心）

**原因**：P1 仅限核心业务正向场景

---

## 快速判断口诀

- **核心正向必 P1**
- **核心反向是 P2**（重要变化）
- **基本常用上 P2**（新增）
- **基本不常给 P3**（新增）
- **基本反向都 P4**
- **不常用的都 P5**

**记忆要点**：P2 包含两类（基本常用 + 核心反向），是占比最高的优先级

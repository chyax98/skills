# 测试用例审查任务

你是 QA 审查者，负责审查已生成的测试用例质量。

## 输入

- **工作区**：`{workspace}`
- **需求文档**：`{requirement_doc}`
- **合并文件**：`{workspace}/{需求名称}-测试用例.jsonl`

## 审查流程

### 1. 格式校验

```bash
python {skill_dir}/scripts/validate.py {workspace}/{需求名称}-测试用例.jsonl
```

确认无格式错误。

### 2. 重复检测

```bash
python {skill_dir}/scripts/detect_duplicates.py {workspace}/{需求名称}-测试用例.jsonl --threshold 0.75
```

对输出的可疑相似对，逐对判断：

| 场景 | 判断 | 处理 |
|-----|------|------|
| 完全重复（复制粘贴错误） | 重复 | 删除其中一个 |
| 同一功能的不同测试角度 | 不重复 | 保留 |
| 同一场景的不同数据组合 | 不重复 | 保留或合并 |
| 跨模块的重复功能 | 可能重复 | 分析业务是否真的重复 |

### 3. 覆盖性检查

对照需求文档检查：

- [ ] 每个功能点是否都有对应测试点？
- [ ] 每个测试点是否至少有 1 正向 + 1 异常/边界用例？
- [ ] 核心功能是否覆盖了更多场景？

### 4. 优先级分布检查

```bash
python {skill_dir}/scripts/stats.py {workspace}/{需求名称}-测试用例.jsonl
```

检查分布是否合理：
- P1: 10-15%
- P2: 25-35%
- P3: 20-30%
- P4: 15-25%
- P5: 5-10%

如偏差过大，分析原因。

### 5. 输出审查报告

写入 `{workspace}/review-report.md`：

```markdown
# 测试用例审查报告

## 概览
- 用例总数：N
- 模块数：N
- 测试点数：N

## 格式校验
✅ 无错误 / ❌ 发现 N 处错误（已修复）

## 重复检测
- 检测到 N 对可疑相似用例
- 判定为重复：N 对（已删除）
- 判定为合理：N 对

## 覆盖性检查
✅ 所有测试点已覆盖 / ⚠️ 以下测试点缺少用例：...

## 优先级分布
| 优先级 | 数量 | 占比 | 目标 | 状态 |
|-------|-----|------|-----|------|
| P1 | N | X% | 10-15% | ✅/⚠️ |
| P2 | N | X% | 25-35% | ✅/⚠️ |
| P3 | N | X% | 20-30% | ✅/⚠️ |
| P4 | N | X% | 15-25% | ✅/⚠️ |
| P5 | N | X% | 5-10% | ✅/⚠️ |

## 结论
✅ 审查通过 / ⚠️ 需要修复 N 项问题
```

## 质量标准

- 格式校验 0 错误
- 无真正重复的用例
- 每个测试点至少 1 正向 + 1 异常/边界
- 优先级分布偏差 ≤10%

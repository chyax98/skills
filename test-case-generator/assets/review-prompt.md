# 测试用例审查任务

你是 QA 复核者，负责审查已生成的测试用例，**发现问题必须修复**。

## 工作区

- **工作区**：`{workspace}`
- **Skill 目录**：`{skill_dir}`

## 关键文件

| 文件 | 说明 |
|------|------|
| `{workspace}/modules.jsonl` | 模块规划和测试项 |
| `{workspace}/cases/*.jsonl` | 已生成的用例 |
| `{skill_dir}/assets/priority-guide.md` | 优先级判定指南（按需读取） |

## 审查流程

### 1. 覆盖完整性

- 每个测试项是否都有用例？
- 每个测试项是否至少有 1 个正向 + 1 个异常/边界？
- `business_value=高` 的是否覆盖更多场景？

**发现遗漏** → 补充用例（ID 从该模块最大序号+1 开始）

### 2. 跨模块一致性

- 优先级分布：P1(10-20%), P2(25-35%), P3(20-30%), P4(15-25%), P5(5-10%)
- 用例名称统一以"验证"开头
- 无重复用例

**发现问题** → 直接修正

### 3. 内容质量

**禁用词检测**：
- 步骤禁用：正确操作、正确输入、按要求操作
- 预期禁用：正确、正常、合适、成功、失败、应该

**发现禁用词** → 改写为具体描述

### 4. 格式校验

```bash
grep -n '�' {workspace}/cases/*.jsonl  # 乱码检查
python {skill_dir}/scripts/validate.py {workspace}/cases/*.jsonl --strict
```

- 测试项覆盖率 = 100%

- 格式校验 0 错误

# 测试用例审查任务

你是 QA 复核者，负责审查已生成的测试用例。

## 工作区

- **工作区**：`{workspace}`
- **Skill 目录**：`{skill_dir}`

## 审查流程

### 1. 格式校验

```bash
# 验证所有模块合并文件
python {skill_dir}/scripts/validate.py {workspace}/*.jsonl --strict
```

脚本会输出格式错误，必须修复。

### 2. 相似度检测（重点）

```bash
# 检测所有合并文件中的相似/重复用例
python {skill_dir}/scripts/detect_duplicates.py {workspace}/{需求名称}-测试用例.jsonl --threshold 0.7
```

**输出**：可疑相似对（综合相似度 ≥ 70%）

**检测维度**：
- 名称相似度（编辑距离）
- 步骤相似度（Jaccard）
- 预期结果相似度（Jaccard）
- 综合相似度 = 名称 40% + 步骤 40% + 预期 20%

**你的任务**：逐对判断是否需要合并/删除

### 3. 逐对裁决相似用例

对每对可疑相似用例判断：

| 场景 | 判断 | 处理 |
|-----|------|------|
| 完全重复（复制粘贴错误） | 是 | 删除其中一个 |
| 同一功能的不同测试角度 | 否 | 保留（可优化命名区分） |
| 同一场景的不同数据组合 | 否 | 保留（可合并为数据驱动测试） |
| 跨模块的重复功能 | 是 | 分析是否业务重复，考虑合并模块 |

**示例**：
- 用例 A："验证用户使用正确密码登录成功"，用例 B："验证用户登录成功" → 重复，删除 B
- 用例 A："验证管理员删除用户"，用例 B："验证普通用户删除用户失败" → 不同角色，保留
- 用例 A："验证输入1个字符的用户名失败"，用例 B："验证输入2个字符的用户名失败" → 同一边界的不同数据点，可合并为1个用例多个数据

### 4. 覆盖性检查

检查每个模块的测试项：
- 每个测试项是否都有用例？（Glob `{workspace}/模块/*.jsonl` 对比规划）
- 每个测试项是否至少有 1 正向 + 1 异常/边界？

### 5. 输出审查报告

写入 `{workspace}/review-report.md`：

```markdown
# 测试用例审查报告

## 概览
- 用例总数：{N}
- 模块数：{N}
- 测试项数：{N}

## 1. 格式校验
- ✅ 无格式错误
- ❌ 发现 {N} 处错误（已修复）

## 2. 相似度检测
- 检测到 {N} 对可疑相似用例（相似度 ≥ 70%）
- 判定为重复：{N} 对（已删除）
- 判定为合理：{N} 对（保留）

### 重复用例清单
| 用例 A | 用例 B | 相似度 | 处理 |
|-------|-------|--------|------|
| 验证用户登录成功 | 验证用户使用正确密码登录成功 | 95% | 删除 A，保留 B（更具体） |

## 3. 覆盖性检查
- ✅ 所有测试项都有用例
- ⚠️  以下测试项只有正向用例，缺少异常/边界：
  - 相框创建/礼物相框创建

## 结论
✅ 审查通过（删除 N 个重复用例，无其他问题）
```

## 质量标准

- 格式校验 0 错误
- 重复用例已消除
- 每个测试项至少 1 正向 + 1 异常/边界
- 步骤和预期描述具体明确

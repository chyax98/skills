# 用户管理系统需求文档

## 项目背景

本系统旨在提供完整的用户生命周期管理功能，包括用户注册、登录、信息维护、权限控制等核心能力。系统需要支持多种用户角色，确保数据安全和操作审计。

## 功能需求

### 用户注册

用户可以通过手机号或邮箱注册账号。注册时需要填写用户名、密码、真实姓名等基本信息。系统应验证手机号和邮箱的唯一性，密码需符合安全策略（至少 8 位，包含大小写字母和数字）。注册成功后发送验证邮件或短信。

### 用户登录

支持用户名、手机号、邮箱三种方式登录。登录时验证账号密码，失败次数超过 5 次后锁定账号 30 分钟。登录成功后生成会话令牌（Token），有效期 24 小时。支持记住登录状态功能。

### 个人信息管理

用户可以查看和编辑个人信息，包括头像、昵称、真实姓名、联系方式、地址等。修改手机号和邮箱需要验证新旧账号。支持修改密码功能，需验证原密码。

### 权限管理

系统支持多角色权限控制，包括普通用户、管理员、超级管理员。不同角色拥有不同的功能权限。管理员可以分配和回收用户权限。所有权限变更需要记录操作日志。

### 账号安全

支持双因素认证（2FA），可选短信或邮箱验证码。提供登录日志查询功能，记录登录时间、IP 地址、设备信息。支持异地登录提醒。用户可以主动登出，清除会话令牌。

## 非功能需求

### 性能要求

系统应支持 1000 并发用户同时在线。登录响应时间不超过 2 秒。用户信息查询响应时间不超过 1 秒。数据库查询需要建立适当索引优化性能。

### 安全要求

密码使用 bcrypt 加密存储，加密强度不低于 10 轮。会话令牌使用 JWT，包含用户 ID 和过期时间。所有敏感数据传输使用 HTTPS 加密。防止 SQL 注入、XSS 攻击、CSRF 攻击。

### 兼容性要求

系统需兼容 Chrome、Firefox、Safari、Edge 最新两个版本。支持响应式布局，适配桌面端和移动端。API 接口遵循 RESTful 规范。

### 可用性要求

系统可用性不低于 99.5%。提供清晰的错误提示信息。界面友好，符合用户习惯。支持中英文双语。

## 数据字典

### 用户表（users）

| 字段名 | 类型 | 说明 | 约束 |
|-------|------|------|------|
| id | bigint | 用户 ID | 主键，自增 |
| username | varchar(50) | 用户名 | 唯一，非空 |
| password | varchar(255) | 密码（加密） | 非空 |
| real_name | varchar(50) | 真实姓名 | 非空 |
| phone | varchar(20) | 手机号 | 唯一 |
| email | varchar(100) | 邮箱 | 唯一 |
| role | varchar(20) | 角色 | 默认 user |
| status | tinyint | 账号状态 | 1=正常，0=锁定 |
| created_at | timestamp | 创建时间 | 默认当前时间 |
| updated_at | timestamp | 更新时间 | 自动更新 |

## 业务规则

1. 用户名长度限制为 3-20 个字符，仅支持字母、数字、下划线
2. 密码必须包含大写字母、小写字母、数字，长度 8-20 位
3. 手机号必须是中国大陆 11 位手机号
4. 邮箱必须符合标准邮箱格式
5. 同一 IP 地址 1 小时内注册次数不超过 3 次
6. 会话令牌过期后需要重新登录
7. 修改密码后，所有已登录会话自动失效
8. 删除用户时采用软删除，保留历史数据
9. 管理员不能修改超级管理员权限
10. 所有敏感操作需要二次验证

## 接口设计

### 用户注册

```
POST /api/v1/users/register
Content-Type: application/json

Request:
{
  "username": "zhangsan",
  "password": "Password123",
  "real_name": "张三",
  "phone": "13800138000",
  "email": "zhangsan@example.com"
}

Response (200):
{
  "code": 0,
  "message": "注册成功",
  "data": {
    "user_id": 12345,
    "username": "zhangsan"
  }
}
```

### 用户登录

```
POST /api/v1/users/login
Content-Type: application/json

Request:
{
  "account": "zhangsan",
  "password": "Password123"
}

Response (200):
{
  "code": 0,
  "message": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "expires_at": "2025-11-28T12:00:00Z",
    "user": {
      "id": 12345,
      "username": "zhangsan",
      "role": "user"
    }
  }
}
```

## 测试要点

1. 验证所有必填字段的空值校验
2. 验证字段长度和格式约束
3. 验证唯一性约束（用户名、手机号、邮箱）
4. 验证密码加密存储
5. 验证登录失败次数限制
6. 验证会话令牌有效期
7. 验证权限控制的准确性
8. 验证并发登录场景
9. 验证异常情况处理（网络异常、数据库异常）
10. 验证安全防护措施（SQL 注入、XSS 等）

## 约束和限制

1. 系统初期仅支持单数据库部署
2. 暂不支持第三方登录（微信、QQ 等）
3. 暂不支持多租户隔离
4. 文件上传大小限制为 2MB（头像）
5. 用户信息修改频率限制为每小时 5 次

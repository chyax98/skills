# 内容结构化策略

本文档提供将分析后的内容组织成思维导图的详细策略。

## 核心原则

### 自顶向下

从整体到细节构建思维导图：
1. 确定一级标题（核心主题）
2. 识别主要维度（二级标题）
3. 逐层展开细节（三到六级）

### 结构化分类

使用一致的分类标准：
- **功能维度**: 做什么、怎么做、为什么做
- **时间维度**: 历史、现状、未来
- **空间维度**: 整体、部分、细节
- **逻辑维度**: 定义、特征、应用、问题

## 层级设计

### 一级标题（根节点）

- 全文唯一
- 简洁明确（5-10 字）
- 准确概括主题

示例：
- `# React Hooks`
- `# 微服务架构`
- `# Git 工作流程`

### 二级标题（主要分支）

- 建议 3-7 个
- 覆盖核心维度
- 并列关系

常见模式：
- **概念类**: 定义 → 特征 → 原理 → 应用
- **技术类**: 概述 → 组件 → 实现 → 最佳实践
- **流程类**: 准备 → 执行 → 验证 → 优化
- **知识类**: 基础 → 核心 → 进阶 → 实战

### 三到六级标题（详细展开）

- 每级不超过 7 个同级节点
- 避免过深层级（建议 ≤5 级）
- 保持逻辑递进

## 内容组织技巧

### 并列关系

同级节点应该：
- 分类标准一致
- 内容互斥
- 合计完整

示例（正确）:
```markdown
## 前端技术栈
### React
### Vue
### Angular
```

示例（错误 - 分类标准不一致）:
```markdown
## 技术栈
### React
### 数据库
### 服务器
```

### 递进关系

父子节点应该：
- 逻辑递进（从抽象到具体）
- 包含关系（父节点包含子节点）
- 层次分明

示例:
```markdown
## 状态管理
### useState
#### 基本用法
#### 注意事项
### useReducer
#### 使用场景
#### 最佳实践
```

## 场景化策略

> **重要**：以下模板采用维度思维组织，避免文档式章节（介绍、背景、总结、学习路径、最佳实践等）

### 概念分析型

结构模板：
```
# [概念名称]
## What - 核心定义
├── 定义
├── 特征
└── 原理

## Why - 价值与问题
├── 解决的问题
└── 带来的价值

## How - 实现方式
├── 应用场景
├── 实现模式
└── 注意事项

## Relationships - 关联概念
├── 相关技术
└── 对比分析
```

### 技术架构型

结构模板：
```
# [系统名称]
## Components - 核心组件
├── 前端模块
├── 后端服务
└── 基础设施

## Interactions - 组件交互
├── 接口设计
└── 通信机制

## Data Flow - 数据流转
├── 输入处理
├── 核心处理
└── 输出呈现

## Quality - 质量属性
├── 性能优化
├── 安全防护
└── 可观测性
```

### 流程梳理型

结构模板：
```
# [流程名称]
## Phases - 主要阶段
├── 阶段一
├── 阶段二
└── 阶段N

## Actors - 参与角色
├── 角色A
└── 角色B

## Resources - 所需资源
├── 输入资源
└── 工具支持

## Outputs - 交付产物
├── 阶段产物
└── 最终产物

## Risks - 风险控制
├── 常见问题
└── 应对策略
```

### 知识体系型

结构模板：
```
# [主题名称]
## What - 领域概述
├── 核心概念
└── 知识边界

## Foundation - 基础知识
├── 基本概念
└── 基础技能

## Core - 核心知识
├── 核心理论
└── 核心技术

## Advanced - 进阶知识
├── 高级理论
└── 综合应用

## Practice - 实战应用
├── 典型场景
└── 案例分析
```

## 内容优化

### 节点简洁化

每个节点应该：
- 1-2 行文字
- 关键词优先
- 避免冗长描述

优化前:
```markdown
### React 是由 Facebook 开发的一个用于构建用户界面的 JavaScript 库
```

优化后:
```markdown
### React 核心特性
```

### 结构扁平化

避免过深嵌套：

优化前（6 级深度）:
```markdown
# 主题
## 分支
### 子分支
#### 详细内容
##### 更详细
###### 太深了
```

优化后（4 级深度）:
```markdown
# 主题
## 分支
### 核心要点1
#### 详细说明
### 核心要点2
#### 详细说明
```

### 平衡性调整

检查并调整：
- 各分支节点数量是否均衡
- 是否有分支过于单薄
- 是否有分支过于臃肿

## 质量检查清单

结构化完成后，检查：

- [ ] 一级标题唯一且准确
- [ ] 二级标题 3-7 个，覆盖核心维度
- [ ] 层级深度 ≤5 级
- [ ] 同级节点分类标准一致
- [ ] 父子节点逻辑递进
- [ ] 每个节点内容简洁（1-2 行）
- [ ] 避免单子节点（考虑合并）
- [ ] 避免同级节点过多（考虑分组）
